마이크로소프트가 Claude Code 라이선스를 줄인 이유, Copilot CLI로의 전환

한 줄 요약
마이크로소프트는 Experiences + Devices 부문의 Claude Code 라이선스 대부분을 6월 30일까지 종료하고 내부 도구인 Copilot CLI 사용을 확대하기로 했습니다.

경쟁사 제품을 썼다는 사실보다 중요한 것

마이크로소프트 개발자들이 Anthropic의 Claude Code를 업무에 사용했다는 사실은 AI 코딩 시장의 경쟁력을 보여줍니다. 그러나 2026년 5월 보도에서 더 중요한 부분은 Experiences + Devices 조직이 라이선스 대부분을 6월 30일까지 종료하고 Copilot CLI로 이동하려 했다는 점입니다.

이유는 성능 하나가 아니다

기업용 AI 도구 선택에는 모델 성능뿐 아니라 비용, 데이터 통제, 보안, 계약, 감사기록, 기존 개발환경과의 통합이 함께 작용합니다. 자체 제품을 가진 회사는 외부 도구 사용료가 커질수록 내부 플랫폼으로 사용을 모을 유인이 큽니다.

“Claude가 나빠서 퇴출됐다”기보다 비용과 제품전략, 내부 표준화를 함께 고려한 결정으로 보는 편이 정확합니다.

Copilot CLI가 노리는 자리

터미널형 AI 도구는 저장소를 읽고 명령을 실행하며 코드를 수정합니다. Microsoft는 GitHub Copilot 생태계를 개발자의 편집기와 터미널, 기업 정책에 연결함으로써 사용량과 데이터를 한 체계 안에서 관리하려 합니다.

기업에 주는 교훈

  • 단일 도구에 전사적으로 종속되지 않도록 합니다.
  • 부서별 비용과 생산성 지표를 따로 봅니다.
  • 모델 교체가 가능한 표준 작업흐름을 만듭니다.
  • 소스코드와 비밀정보가 어디로 전송되는지 확인합니다.

AI 코딩 도구의 승부는 벤치마크뿐 아니라 기업이 통제 가능한 운영비와 관리성에서 갈릴 가능성이 큽니다.

핵심 정리

마이크로소프트는 Experiences + Devices 부문의 Claude Code 라이선스 대부분을 6월 30일까지 종료하고 내부 도구인 Copilot CLI 사용을 확대하기로 했습니다. 단일 사례나 수치만으로 전체 산업의 승패를 단정하기보다 비용, 성능, 보안과 운영조건을 함께 살펴야 합니다.
